# Global friends and messaging

The owner confirmed that user-to-user friend requests and messages work in Street Empire. This change extends the same friends and inbox to the rest of HYPHSWORLD, including music, Creator Worlds, shop, vault and games pages. The Friends button shows unread messages and incoming requests. The panel supports public username/name search, friend acceptance, private text conversations, older history, blocking/unblocking and reporting a received message. Existing Street Empire friends and conversation history are shared; no second account or graph is created.

The shared `auth-client.js` and `global-my-id.js` entry points load the widget once. Super Strike's effects entry loads it on game routes too; its persistent export override has the same entry so future exports keep the control. Street Empire retains its existing built-in Friends panel and uses the same backend.

Only accepted friends see each other's status through the existing authenticated social RPC. Active visible pages publish `available`, or `playing` on game routes, to the existing presence sessions. Hidden, offline and departing pages stop their own session; failed unload requests expire after 75 seconds. Separate tabs have separate session IDs, and the existing eight-session cap still applies. A five-second foreground refresh updates contacts/unread state and an open conversation; presence renews every 25 seconds. No messages are read in the background while the panel is closed. No new database migration or grants are required.

The client uses the actual Supabase session and denies anonymous sessions. Every social request includes the expected account ID; the server verifies caller identity, active profile, friendship and bidirectional blocks. Delayed account/search/chat responses are discarded. Message retry nonces are retained for an unchanged draft after ambiguous network failures. Names and messages are rendered as text. Messages remain access controlled, not end-to-end encrypted. No message content is saved to browser storage.

Validation: Jest exercises shared inbox data, account switching, stale searches, same-peer chat reopening, send retries, plain-text rendering, hidden-tab heartbeat ordering, BFCache resume, anonymous denial and friend acceptance/blocking. Coverage checks every public root HTML page and Super Strike's persistent export hook. Browser layout checks cover phone and desktop viewports using synthetic accounts only. The existing production social/presence functions and grants were checked read-only; production accounts and messages were not changed. Physical two-device checks remain appropriate after merge and deployment.
